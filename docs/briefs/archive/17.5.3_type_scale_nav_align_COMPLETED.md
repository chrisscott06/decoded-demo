After Brief 17.5.2 close (9fd24aa), Consumption tab review found two real issues that previous briefs missed because the spec didn't capture them:

1. **Type scale never written.** The tool has palette tokens, ribbon-height tokens, page-edge-x token — but no canonical type scale. Brief 17.5.2 specified the body container but didn't say the navs sit inside it too. Spec miss.

Type is **fluid via CSS `clamp()`** so the same scale works on a 1440 laptop (small body) and a 1920+ presentation TV (larger body, capped). The body grows from **14px at 1440 viewport** to **18px at 2560 viewport** (capping there), scaling smoothly between. One CSS function per role, no media queries.

## The type scale — canonical, first time

**Six roles, fluid via clamp().** Each role grows linearly between viewport widths **1440px (min) and 2560px (max)**, capped at both ends. Below 1440 → uses min. Above 2560 → uses max.

| Token | Min (≤1440vw) | Max (≥2560vw) | Line-height | Family | Use |
|---|---|---|---|---|---|
| `--text-page-title` | 28px | 36px | 1.15 | `--font-heading` | Page titles (e.g. "Energy", "Carbon") |
| `--text-section-title` | 20px | 26px | 1.25 | `--font-heading` | Major section titles within a page |
| `--text-subsection-title` | 16px | 20px | 1.3 | `--font-heading` | Subsection titles ("The portfolio in one line.", coral on cream/navy) |
| `--text-body` | **14px** | **18px** | 1.55 | `--font-body` | All body text, narrative paragraphs |
| `--text-body-small` | 12px | 15px | 1.5 | `--font-body` | Scope statements, italic captions under headlines |
| `--text-caption` | 11px | 13px | 1.4 | `--font-body` | Axis labels, micro-labels, source attributions |

**Computed clamp() declarations** (derived from min/max + viewport range):

```
--text-page-title:       clamp(28px, 17.71px + 0.714vw, 36px);
--text-section-title:    clamp(20px, 12.29px + 0.536vw, 26px);
--text-subsection-title: clamp(16px, 10.86px + 0.357vw, 20px);
--text-body:             clamp(14px,  8.86px + 0.357vw, 18px);
--text-body-small:       clamp(12px,  8.14px + 0.268vw, 15px);
--text-caption:          clamp(11px,  8.43px + 0.179vw, 13px);
```

**Verification at known viewports** (the middle term hits these values):
- 1440 viewport, body: 14.00px ✓
- 1920 viewport, body: 15.71px (≈ 16, comfortable presentation size)
- 2560 viewport, body: 18.00px (capped)
- 3840 viewport (4K), body: 18.00px (capped) ✓

**Where the scale lives:** declared in `eir/src/index.css` (or a new `eir/src/tokens/type.css` imported globally), alongside palette and ribbon tokens. **No font-size in component-local CSS or inline styles after this brief lands.** Every text element references a role token. Falsifiability: after Part 1, `grep -rn 'font-size:' eir/src --include='*.jsx' --include='*.tsx'` should return zero hits in component files; in CSS, every hit should reference a `var(--text-*)` token, with one or two acceptable exceptions (e.g. icon-glyph buttons) documented in the close report.

## The alignment fix

Brief 17.5.2's centred 1280px container applies to the **body** but not the **navs**. The navs use viewport-edge padding. Result: misaligned left edges.

**The fix:** all three nav strips (primary `Home/Portfolio/Site/...`, secondary `Map/Energy`, tertiary `Consumption/Heating/Power/Metering`) wrap their contents in the **same centred 1280px container** the body uses. Approach:

- The nav strip itself (the coloured/styled band) stays viewport-edge-to-viewport-edge (so its background spans the screen).
- Its **content** (the buttons/tabs) sits inside an inner `<div>` with `max-width: 1280px; margin: 0 auto; padding-left/right: var(--page-edge-x)`.
- This is the standard "full-bleed band, centred content" pattern.

Result: all four bands (3 navs + body) share one inner left edge at the same x-coordinate. At 1920 viewport, that left edge sits at x=320. At 1440 viewport, x=80.
