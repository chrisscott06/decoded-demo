## The spec — measured numbers, applied at 1920×1080

### Page container

- **Max-width: 1280px**, centred horizontally in viewport.
- **Side padding (page edge to container): minimum 32px.** At 1920 viewport, ~320px each side. At narrower viewports, the container scales down; side padding never goes below 32px.
- **Container has a soft edge** — no border by default, but content NEVER touches the viewport edge. This is the breathing rule.

### Inner column structure

- **Two-column grid inside the container:** narrative pane (left) + graphic pane (right).
- **Narrative pane width: flex per page within a band of 400–520px.** Page-author choice driven by the **fit test** below.
- **Gutter between columns: 48px** fixed.
- **Graphic pane: fills remaining width** (i.e. 1280 − narrative_width − 48 = 712–832px depending on narrative).

### Narrative-width fit test

A deterministic test, not aesthetic judgement:

1. Start at the **wide end** of the band: **480–520px**.
2. Render the narrative at 1920×1080 (the presentation target).
3. **If the narrative fits without internal scroll: keep it.** The narrative pane stays exactly as wide as needed for the prose to fit cleanly.
4. **If the narrative overflows: narrow the column** until either (a) it fits, or (b) it hits the floor of **400px**.
5. **If it still overflows at 400px: the narrative is allowed to scroll internally** — the graphic pane stays put. Page-level scroll never engages.

The decision is page-by-page. Different sub-tabs within the same page CAN have different narrative widths if their prose differs in length. This is intentional flexibility.

### Vertical rhythm

Top to bottom on the Energy page:

- **Primary nav strip (Home / Portfolio / Site / Insights / GRESB): 44px tall.**
- **Secondary nav strip (Map / Energy): 36px tall.**
- **Tertiary sub-tab strip (Consumption / Heating / Power / Metering): 32px tall.**
- **Gap from tertiary sub-tabs to page-title-or-toggle-row: 24px.**
- **Top toggle row (if present, as on Consumption): 32px tall.**
- **Gap from toggle row to chart canvas: 32px.**
- **Chart canvas: fills remaining vertical space**, target ~820px at 1920×1080.
- **Bottom margin (chart bottom to container bottom): 48px minimum.**

### Subsection rhythm (inside narrative)

Matches EOC's Trajectory page:

- **Subsection title:** 20-24px font size, with a **1px underline 4–6px below the baseline.**
- **Gap from subsection underline to body text: 16px.**
- **Body text line-height: 24px.**
- **Gap between paragraphs in same subsection: 12px.**
- **Gap between subsections: 48px.**

## Principles

1. **Content NEVER touches the viewport edge.** This is the breathing rule and the most important single guard. Side padding ≥ 32px at all viewport widths.
2. **The numbers above are the spec. Not "match EOC vibe" — match these.** The fit test is deterministic; the rhythm is measurable; verification is by ruler-grep against computed CSS values.
3. **1920×1080 is the target viewport.** It's the presentation use case. 1440×900 still works (smaller container, same proportions), but 1080 is the screen the tool is designed to look right on.
4. **Narrative width is flex per page within the band.** The fit test runs at 1920×1080. Different sub-tabs may land at different widths within the band — that's intentional, not a regression.
5. **No element of layout state is "magic."** Every measurement in the rendered page maps to a value in the spec. Anywhere Claude Code is unsure, refer back to the EOC reference screenshots and measure.
6. **Browser-verify is the gate** (Hard Rule 9). Mandatory screenshots at **1920×1080** (not 1440×900) — this is the presentation target. Verification at 1440×900 also performed to confirm graceful scale-down, but the design target is 1920×1080.
