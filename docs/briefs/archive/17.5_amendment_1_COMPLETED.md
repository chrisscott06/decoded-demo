## Why this amendment

Part 4 checkpoint screenshot review (Chris, 3 Jun) found the new Consumption chart functionally correct but visually unfinished in four specific ways. Below are the four corrections. None changes the data; all change presentation.

1. **Legend takes too much vertical space.** The 2×3 grid at the bottom of the graphic eats a slab of vertical space and uses the full width. The control surface should be **a single compact horizontal row of toggle buttons sitting at the top of the chart**, replacing the bottom grid entirely.
2. **GRESB-26 sites at 0.4 opacity look washed out.** Replace with **darker shades** of the same red and yellow — visually present, clearly distinct, still readable. Also simplify their composition (see Part 5).
3. **No motion.** Part 1 set up the design tokens but the framer-motion transitions the brief asked for were never wired into the chart. Bars don't grow on render, segments don't transition smoothly on toggle, sub-tab switches snap instead of fading.
4. **Vertical space across the page generally too airy.** The right pane carries large gaps between elements (between sub-tab strip and chart, between chart and bottom). Tighten throughout.

---

## Decisions taken (Claude Chat → push back if wrong before Claude Code starts)

**Toggle logic — AND, not OR.** A segment is visible if (its commodity toggle is on) AND (its party-type toggle is on). Default = everything on. Clicking "Landlord" off hides both landlord-gas and landlord-electricity segments across every bar. Clicking "Gas" off hides all gas segments. Both off → only sub-metered-electricity and estimated-electricity remain. Six toggles, predictable behaviour.

**GRESB-26 composition — simplified to 2 segments.** Out-of-scope bars (Sonning Common, Edwalton Office) render as just **total gas + total electricity in darker shades**, not the full 5-segment landlord/sub-metered/estimated breakdown. They're out of scope; the internal breakdown isn't analytically interesting. Simpler, less palette competition.

If Chris pushes back: alternative is OR logic for toggles, or the full 5-segment composition with darker shades — both buildable, just flag before Part 5 starts.

## Part 5 (NEW) — Compact toggle row + GRESB-26 darker shades

Replaces both the existing 2×3 legend grid (delete) and the top-of-chart GRESB-26 pill (delete).

**Build the compact toggle row** at the top of the graphic pane, in this exact order, left to right:

| Toggle | Controls | Icon hint |
|---|---|---|
| **Landlord** | landlord-gas + landlord-electricity (row of segment matrix) | IV monogram |
| **Sub-metered** | submetered-gas + submetered-electricity (row) | small gauge / dot grid |
| **Estimated** | estimated-gas + estimated-electricity (row) | dotted-circle |
| **Gas** | all three gas segments (column) | red square swatch |
| **Electricity** | all three electricity segments (column) | yellow square swatch |
| **GRESB 26** | Sonning Common + Edwalton Office bar visibility | "26" badge |

Each toggle is a small pill-shaped button with the icon and label. Active state = filled with its colour family token + bold label. Inactive state = outlined + muted label. All six default to active.

**Segment visibility rule:** a segment renders only when both its row toggle and its column toggle are on. The GRESB-26 toggle controls whether those two sites show at all (cycle: visible-darker → hidden).

**GRESB-26 dark shades** — declare two new tokens:
- `--color-gresb26-gas` — a clearly darker red than `--color-energy-gas-landlord`
- `--color-gresb26-elec` — a clearly darker yellow than `--color-energy-elec-landlord`

Out-of-scope sites render with two segments only (total gas in dark-red, total electricity in dark-yellow), stacked, using these tokens. **No internal party-type breakdown for these two bars.**

**Delete the bottom legend grid entirely.** No legend remains. The top toggle row carries everything.

Commit `Brief 17.5 Part 5: compact toggle row + GRESB-26 dark shades`.

## Part 6 (NEW) — Motion + vertical space tighten

**Motion (framer-motion, already installed per Brief 14):**

1. **Bar growth on first render** — each bar segment animates from height 0 to its computed height over ~600ms, staggered slightly per bar (left-to-right ripple, ~30ms per site).
2. **Segment height transitions on toggle** — when a segment is toggled off, it animates out (height collapses, opacity fades); when toggled on, the reverse. ~300ms. Other segments smoothly adjust their stack position.
3. **Sub-tab switch transition** — the graphic pane (and narrative pane) fade-and-grow on Consumption ↔ Heating ↔ Power ↔ Metering switches, per the EOC reference pattern from Brief 17.5 Part 1. ~400ms. Existing graphic fades out, new one fades in slightly scaled-up.

CLAUDE.md Rule 10 still applies — the motion wrappers must not break Recharts' ResponsiveContainer height resolution. If conflict surfaces, the Brief 13 `isAnimationActive={false}` pattern may apply per-Bar; check during build.

**Vertical space tighten:**

- Tighten gap between secondary nav ("Map · Energy") and tertiary tabs ("Consumption · Heating · Power · Metering") — currently too airy.
- Tighten gap between tertiary tabs and the chart title.
- Tighten gap between chart and the x-axis site icons + labels (currently sit too low).
- Verify on a 1440×900 viewport that the chart now reads as a single confident composition rather than scattered elements with whitespace between.

Commit `Brief 17.5 Part 6: motion + vertical tighten`.
