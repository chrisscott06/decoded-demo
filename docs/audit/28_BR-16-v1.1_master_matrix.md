## Implementation notes

### Single-script approach

All five brief sections applied via one patch script at `docs/briefs/active/28_BR-16-v1.1_patch.py` (~360 lines). Section 1-2 read from `28_BR-16-v1.1_corrections.json`; Section 3-4 hard-code the waterfall2026 blocks + cycle panels from the brief markdown (they're not in the corrections JSON). Section 5 derives aspect totals from `corrections.aspects` with a single `GHG → "GHG Emissions"` name alias to match the project's canonical aspect name.

### Back-compat strategy

The new v1.1 schema (`defendable`/`target`/`stretch`/`status` per indicator; `waterfall2026.blocks[].items[]` for the waterfall) breaks the existing component contracts. Two paths:
- **Aggressive:** refactor Overview / Aspects / Forward to read v1.1 names directly
- **Conservative:** keep v1.0 field names as aliases mirrored from v1.1 values, so existing components render unchanged

This patch goes **conservative**. Every indicator carries both schemas; `forwardPlanning.waterfall.blocks` is repaved with a 50-entry flat array that Forward.jsx's existing buildLayout walks unchanged. UI refactor is deferred as a follow-up (see Known follow-ups).

### SE2 → SE2.1 rename

GRESB 2026 Standard Updates split the legacy monolithic `SE2` (employee survey) into `SE2.1` (vintage-checked employee survey) + `SE2.2` (retired). Brief 28's corrections name the new code `SE2.1`. The existing JSON carried `SE2` from earlier briefs. Patch script renames in place via `INDICATOR_CODE_RENAMES = {"SE2": "SE2.1"}`. Idempotent on re-run (no SE2 left to rename second pass).

### RES6 (out-of-scope) preservation

v1.1 brief doesn't mention RES6 — it stayed at v1.0's `max=0`, `scoring=not-applicable`. Patch script explicitly re-applies that state every run so re-introductions or accidental drift get caught.
